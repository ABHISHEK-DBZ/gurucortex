## 1. Intent and The Why

GuruCortex 2.0 introduces an advanced cognitive learning suite: Concept Reality Navigator, Revision Intelligence (SM-2 spaced repetition), Cognitive Learning Coach, Career Pathways, Focus Intelligence, Parent Connect, and Institution Mode. 

Users need interaction to be **real-time and fully functional**:
- Explaining complex physics/engineering concepts should stream tokens sub-second as they are generated by LLMs, eliminating 10–15 second blank pauses.
- All student progress, flashcard reviews, focus sessions, and coach recommendations must persist reliably in a live local SQLite database.
- The system must provide automated end-to-end verification proving every real-time endpoint and database transaction works without mocks.
- The repository must be clean of temporary mutation scripts and prepared for atomic commits.

---

## 2. Goals, Non-Goals, and Anti-Goals

### Goals
- **Real-Time Streaming:** Add native asynchronous Server-Sent Events (SSE) streaming (`stream_generate`) in `backend/app/services/llm_client.py` and expose streaming endpoints in routers (`/api/v1/visual/reality/stream`, `/api/v1/coach/stream`).
- **Live Database Persistence:** Ensure all 7 engines write to and read from `gurucortex.db` via `backend/app/services/database.py` with verified schemas.
- **Frontend Real-Time Integration:** Update `frontend/lib/api-client.ts`, `ConceptRealityNavigator.tsx`, and `CognitiveCoach.tsx` to read the SSE stream token-by-token.
- **Automated Verification:** Replace ad-hoc scripts with a reproducible `pytest` suite (`backend/tests/test_realtime_api.py`) validating all 11 endpoints, database state, and streaming responses live.
- **Repository Hygiene:** Prune temporary generator scripts (`backend/add_streaming_to_llm.py`, `backend/update_main.py`, `frontend/update_api_client.py`) and clean router imports in `backend/app/main.py`.

### Non-Goals
- Replacing the Next.js frontend framework or Tailwind styling.
- Introducing external managed cloud databases (e.g., PostgreSQL/Supabase); SQLite remains the canonical local embedded engine.
- Re-architecting existing working non-streaming endpoints (streaming endpoints supplement and enhance, rather than replace, existing endpoints).

### Anti-Goals
- **Mock-Only Verification:** Replacing real execution with hollow mocked unit tests that don't prove live SQLite or LLM pipeline functionality.
- **Simulated Client Typewriters:** Faking real-time on the client with artificial delays after waiting for a complete JSON response.
- **Monolithic Commits:** Staging all files in one massive untracked commit.

## 3. Constraints
- **Python Runtime:** Python 3.10+ with FastAPI, aiosqlite, httpx, and uvicorn.
- **Frontend Runtime:** Next.js 14 App Router, React 18, TypeScript, Tailwind CSS, Lucide icons.
- **API Protocol:** REST + Server-Sent Events (`text/event-stream`) over HTTP/1.1.
- **Database Engine:** SQLite (local file `gurucortex.db` with WAL mode).

---

## 4. Approaches Considered

### Approach 1: Native Server-Sent Events (SSE) Streaming + Live Persistent SQLite Engine (Selected)
- **Architecture:** Add `stream_generate` to `LLMClient` to yield chunks directly from Groq/Ollama or cognitive fallback generator. Add FastAPI `StreamingResponse` endpoints. Update frontend `api-client.ts` to consume streams via `ReadableStream` / `TextDecoder` and SSE line parsing. Use live SQLite tables for all state. Test live with `TestClient`.
- **Trade-offs:** Requires coordinating SSE handling across backend and frontend, but provides authentic sub-second response times and complete real-time capability.
- **Decision:** Selected because the user explicitly requires "all realtime fully functional".

### Approach 2: Client-Side Simulated Streaming with Direct Non-Streaming Endpoints (Rejected)
- **Architecture:** Keep backend responses standard JSON. Frontend simulates streaming via timed character display.
- **Trade-offs:** Cheaper to build, but fails to reduce network wait time and does not provide real-time AI generation. Rejected.

## 5. Technical Specifications & Architecture

### 5.1 LLM Client Streaming (`backend/app/services/llm_client.py`)
Add `async def stream_generate(self, prompt: str, system_prompt: Optional[str] = None, temperature: float = 0.4, max_tokens: int = 1500) -> AsyncGenerator[str, None]`:
- Stream from Groq (`stream=True`) parsing `data: {"choices": [{"delta": {"content": "..."}}]}`.
- If Groq unavailable, stream from Ollama (`/api/generate` with `stream=True`).
- If offline or missing credentials, fallback to an asynchronous cognitive token generator that streams structured, context-aware analysis with realistic pacing (40ms chunks).

### 5.2 Real-Time Streaming Endpoints
- `POST /api/v1/visual/reality/stream`:
  - Body: `{ "concept": str, "depth": str }`
  - Returns: `StreamingResponse(content=..., media_type="text/event-stream")`
  - Protocol: Standard SSE frames (`data: <token>\n\n`, ended by `data: [DONE]\n\n`).
  - Streams intuitive mechanical breakdown and physical laws for the concept.
- `POST /api/v1/coach/stream`:
  - Body: `{ "student_id": str, "query": str }`
  - Returns: `StreamingResponse(content=..., media_type="text/event-stream")`
  - Protocol: Standard SSE frames (`data: <token>\n\n`, ended by `data: [DONE]\n\n`).
  - Streams live research-backed strategy guidance tailored to the student's question.

### 5.3 Live SQLite Database Schema Harmonization (`backend/app/services/database.py`)
Preserve and enforce existing canonical schema definitions in `database.py`:
- `flashcards` (id, user_id, front_prompt, back_answer, topic, interval_days, repetitions, ease_factor, next_review, created_at)
- `coach_recommendations` (id, student_id, difficulty_pattern, recommended_strategy, actionable_steps, duration_minutes, evidence_base, status, created_at)
- `student_projects` (id, student_id, title, subject, description, skills_acquired, outcome, completed_at)
- `focus_sessions` (id, student_id, topic, planned_duration_minutes, actual_duration_minutes, focus_score, distractions_blocked, completed_at)
- `parent_student_links` (id, student_id, link_code, parent_email, is_verified, created_at)
- `concept_reality_cache` (id, concept_name, domain, reality_json, created_at)

### 5.4 Frontend Real-Time Stream Consumer (`frontend/lib/api-client.ts`)
Add SSE stream consumer functions:
```typescript
async streamRealityExplanation(concept: string, onToken: (token: string) => void): Promise<void>
async streamCoachAdvice(query: string, onToken: (token: string) => void): Promise<void>
```
Implementation parses incoming SSE lines (`data: ...`), drops control headers, and dispatches tokens to `onToken()`.

### 5.5 UI Integration
- **Concept Reality Navigator (`frontend/components/ConceptRealityNavigator.tsx`):**
  When exploring a concept, real-time tokens stream live into the prominent "Physical Mechanism & Intuitive Breakdown" viewer as they arrive, alongside the structured reality cards.
- **Cognitive Coach (`frontend/components/CognitiveCoach.tsx`):**
  Includes an interactive "Ask Cognitive Coach" query box at the top of the Coach tab. When submitted, advice streams token-by-token in real-time into an active coaching response window.

### 5.6 Automated Test Suite (`backend/tests/test_realtime_api.py`)
FastAPI `TestClient` suite running against actual application and real SQLite database:
- Test 1: Health check endpoint `/api/v1/health`.
- Test 2: Reality Navigator live endpoint & SSE streaming endpoint (verifying token stream & `[DONE]`).
- Test 3: Revision dashboard & SM-2 flashcard calculation and database persistence.
- Test 4: Cognitive coach recommendations, live coach streaming, and project additions.
- Test 5: Career pathways and telemetry retrieval.
- Test 6: Focus dashboard session tracking.
- Test 7: Parent connect code generation and dashboard retrieval.
- Test 8: Institution mode analytics and interventions.
- Resilient offline fallback: tests assert valid streaming output and database persistence regardless of whether external Groq API keys are present.

### 5.7 Repository Hygiene & Atomic Commits
- Prune temporary generator scripts: `backend/add_streaming_to_llm.py`, `backend/update_main.py`, `frontend/update_api_client.py`.
- Clean router loading in `backend/app/main.py`.
- Stage commits in logical slices:
  1. `feat(backend): implement SSE streaming in LLMClient and real-time routes`
  2. `feat(frontend): integrate live SSE stream consumers in Reality Navigator and Cognitive Coach`
  3. `test(backend): add end-to-end automated pytest suite for live endpoints and streaming`
  4. `chore: clean temporary mutation scripts and update documentation`

## 6. Decisions Settled During Builder Review
- **Database Schemas:** Canonical schemas from `database.py` are preserved intact to guarantee zero breaking changes for existing endpoints.
- **SSE Wire Format:** Standard W3C `data: <token>\n\n` with `data: [DONE]\n\n` sentinel.
- **Offline Reliability:** Tests verify streaming token delivery using either live Groq (if key present) or the live fallback generator (if absent), ensuring tests run smoothly in CI or local setups.
